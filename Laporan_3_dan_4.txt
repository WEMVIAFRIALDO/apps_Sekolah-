LAPORAN 3
PENGEMBANGAN BACKEND API DAN KONFIGURASI DATABASE PADA SISTEM SALUT

1. Konfigurasi Lingkungan Backend (Laravel)
Pada tahap ini, dilakukan persiapan lingkungan backend menggunakan framework Laravel. Konfigurasi awal difokuskan pada pengaturan variabel lingkungan di dalam file .env, khususnya untuk menghubungkan aplikasi Laravel dengan database relasional (MySQL). Langkah ini krusial untuk memastikan aplikasi dapat berkomunikasi dengan sistem penyimpanan data.
[MASUKKAN SCREENSHOT: Tampilan file .env yang menunjukkan konfigurasi koneksi DB_CONNECTION, dll]

2. Pembuatan Struktur Database (Migration dan Model)
Setelah koneksi berhasil, tahap selanjutnya adalah merancang struktur database yang mendukung sistem multi-role (Admin, Guru, Siswa Aktif, Alumni). Pembuatan tabel dilakukan menggunakan fitur Migration bawaan Laravel agar skema database lebih terstruktur. Selain itu, dibuat juga file Model (seperti GraduationSchedule.php dan User.php) untuk merepresentasikan tabel-tabel tersebut di dalam kode.
[MASUKKAN SCREENSHOT: Tampilan kode file Migration atau Model di VS Code]
[MASUKKAN SCREENSHOT: Tampilan tabel-tabel yang sudah berhasil di-migrate ke database (foto dari phpMyAdmin)]

3. Pembuatan Endpoint API dan Implementasi Autentikasi JWT
Sistem SALUT menggunakan arsitektur Client-Server, sehingga diperlukan pembuatan API (Application Programming Interface). Untuk menjaga keamanan data dan komunikasi, diimplementasikan autentikasi berbasis token menggunakan JWT (JSON Web Token). Setiap akses dari aplikasi mobile wajib menyertakan Bearer Token.
[MASUKKAN SCREENSHOT: Tampilan kode routing pada file routes/api.php atau fungsi Login pada Controller]

4. Pengujian API (API Testing)
Untuk memastikan endpoint API dan autentikasi JWT berjalan dengan baik sebelum diintegrasikan ke aplikasi mobile, dilakukan pengujian menggunakan perangkat lunak API Client (seperti Postman atau Thunder Client). Pengujian dilakukan dengan mengirimkan request login, dan memastikan server merespons dengan mengembalikan token akses yang valid.
[MASUKKAN SCREENSHOT: Tampilan aplikasi Postman/Thunder Client hasil Response sukses (200 OK)]

5. Penyimpanan Repositori Backend ke GitHub
Setelah kerangka dasar backend selesai dan diuji, seluruh perubahan kode (source code) disimpan ke version control system GitHub. Hal ini bertujuan untuk mengamankan data proyek dan memudahkan proses pelacakan perubahan kode di masa mendatang.
[MASUKKAN SCREENSHOT: Tampilan terminal VS Code saat melakukan perintah 'git push' untuk backend]
[MASUKKAN SCREENSHOT: Tampilan repositori Backend SALUT di website GitHub]

LAPORAN 4
PENGEMBANGAN ANTARMUKA MOBILE (FLUTTER) DAN INTEGRASI API

1. Pembuatan Antarmuka Pengguna (UI) Utama
Pada tahap ini, pengembangan beralih ke sisi frontend mobile menggunakan Flutter. Langkah pertama adalah menerjemahkan desain (mockup) menjadi kode Dart untuk membentuk antarmuka pengguna (UI). Fokus utama pada tahap ini adalah pembuatan halaman autentikasi (Login Page) dan halaman utama (Dashboard Page) yang responsif dan sesuai dengan estetika proyek.
[MASUKKAN SCREENSHOT: Tampilan potongan kode file login_page.dart atau dashboard_page.dart di VS Code]

2. Integrasi HTTP Request dan Pengelolaan Token JWT
Agar aplikasi mobile tidak sekadar menampilkan UI statis, dilakukan integrasi dengan Backend API yang telah dibuat pada Laporan 3. Aplikasi Flutter dikonfigurasi untuk dapat melakukan HTTP POST request ke server saat pengguna melakukan login. Jika berhasil, aplikasi akan menyimpan token JWT ke dalam penyimpanan lokal perangkat agar pengguna tetap masuk (logged in).
[MASUKKAN SCREENSHOT: Tampilan potongan kode fungsi login/HTTP request di Flutter]

3. Simulasi dan Pengujian Aplikasi pada Perangkat
Setelah integrasi selesai, aplikasi dijalankan (Run/Debug) pada emulator atau perangkat Android fisik. Pengujian dilakukan dengan memasukkan kredensial login untuk memverifikasi apakah aplikasi berhasil terhubung ke server dan berpindah dari halaman Login menuju Dashboard.
[MASUKKAN SCREENSHOT: Tampilan halaman Login aplikasi SALUT yang sedang berjalan di HP/Emulator]
[MASUKKAN SCREENSHOT: Tampilan halaman Dashboard aplikasi SALUT di HP/Emulator setelah login]

4. Implementasi Logika Dynamic UI Rendering (Role-Based)
Sesuai dengan aturan sistem SALUT, tampilan antarmuka harus dinamis menyesuaikan role (peran) pengguna. Oleh karena itu, diterapkan logika kondisional di mana menu dan widget yang ditampilkan untuk 'Siswa Aktif' akan berbeda dengan yang ditampilkan untuk 'Alumni'.
