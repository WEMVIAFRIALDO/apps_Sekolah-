BAB I: PENDAHULUAN DAN GAMBARAN UMUM SISTEM SALUT

1.1 Latar Belakang Masalah

Institusi Sekolah Menengah Kejuruan (SMK) memiliki karakteristik pendidikan yang berorientasi pada kesiapan kerja, kewirausahaan, serta kelanjutan studi ke jenjang pendidikan tinggi. Namun, dalam tata kelola administrasi kelulusan dan pemantauan karir lulusan, sebagian besar institusi pendidikan masih menghadapi tantangan operasional yang signifikan. Berkas kelulusan seperti Ijazah, Surat Keterangan Lulus (SKL), dan transkrip nilai akademik sering kali masih dikelola dalam bentuk fisik yang rentan mengalami kerusakan, pemalsuan, atau kehilangan dalam kurun waktu tertentu.

Di sisi lain, kebutuhan pelacakan jejak alumni (tracer study) menjadi instrumen evaluasi akreditasi dan pemutakhiran kurikulum yang sangat vital bagi SMK. Ketiadaan sistem pendataan yang terintegrasi secara digital menyebabkan pihak sekolah kesulitan memetakan tingkat keterserapan lulusan di Dunia Usaha dan Dunia Industri (DUDI), perguruan tinggi mitra, maupun sektor wirausaha mandiri. Siswa juga memiliki beragam sertifikat uji kompetensi kejuruan dan portofolio keahlian yang belum terakomodasi secara resmi ke dalam format Surat Keterangan Pendamping Ijazah (SKPI).

1.2 Solusi yang Dikembangkan: Sistem SALUT

Untuk menjawab tantangan tersebut, dikembangkan sistem SALUT (Sistem Arsip Kelulusan dan Tracer Study Terpadu). SALUT dirancang sebagai ekosistem teknologi modern berbasis multi-platform yang menghubungkan pihak sekolah (administrator dan guru), siswa aktif tingkat akhir, serta alumni dalam satu kesatuan sistem informasi yang aman, cepat, dan transparan.

BAB II: LAPORAN 1 & 2 - INSTALASI DAN PERSIAPAN ENVIRONMENT

Pengembangan aplikasi mobile berbasis cross-platform membutuhkan persiapan lingkungan kerja (development environment) yang matang dan terkonfigurasi dengan tepat. Pada tahap awal ini, dilakukan serangkaian instalasi piranti lunak fundamental yang mencakup Flutter SDK, Java Development Kit (JDK), Visual Studio Code beserta ekstensinya, Android Studio, Android SDK Command-line Tools, CMake, serta Android NDK.

2.1 Akses Dokumentasi Resmi Flutter SDK

Pada bagian ini, saya mengakses situs web dokumentasi resmi Flutter (docs.flutter.dev) untuk mengikuti prosedur instalasi standar yang direkomendasikan bagi sistem operasi Windows 64-bit.

2.2 Pengunduhan Paket Bundel Flutter SDK

Selanjutnya, saya mengunduh bundel instalasi Flutter SDK versi stabil terbaru (flutter_windows_3.47.6-stable.zip) melalui menu Install manually untuk sistem operasi Windows.

2.3 Konfigurasi System Environment Variables

Setelah mengekstrak file Flutter SDK, saya mendaftarkan direktori instalasinya, yaitu C:\Fluttersetup\flutter_windows_3.47.4-stable\flutter\bin, ke dalam System Environment Variables. Langkah ini dilakukan agar perintah-perintah eksekusi Flutter dapat diakses secara global melalui command line interface atau terminal di VS Code.

2.4 Verifikasi Deteksi Flutter Melalui Command Prompt

Untuk memastikan instalasi Flutter SDK berhasil dan jalurnya terbaca oleh sistem, saya menjalankan perintah flutter --version melalui Command Prompt. Hasilnya menunjukkan bahwa sistem telah berhasil mendeteksi Flutter versi 3.47.6 beserta kelengkapannya, termasuk Dart versi 3.13.5.

2.5 Pengunduhan Java Development Kit (JDK 21)

Pada tahap awal persiapan lingkungan kerja, saya mengunduh Java Development Kit (JDK) versi 21.0.2 berformat zip khusus untuk sistem operasi Windows 64-bit melalui situs resminya guna mendukung kompilasi proyek Android berbasis Gradle.

2.6 Verifikasi Pendaftaran Jalur JDK

Setelah mengekstrak dan mendaftarkan jalur JDK ke dalam sistem (Environment Variables), saya memverifikasi instalasinya melalui terminal VS Code menggunakan perintah java -version. Hasilnya menunjukkan bahwa OpenJDK versi 21.0.2 telah berhasil terbaca oleh sistem.

2.7 Pemasangan Ekstensi Flutter & Dart pada Visual Studio Code

Pada tahap persiapan teks editor, saya memasang ekstensi resmi Flutter di dalam Visual Studio Code agar editor memiliki dukungan penuh untuk menulis kode, navigasi widget, hot reload, dan proses debugging aplikasi secara interaktif.

Selain ekstensi Flutter, saya juga memastikan ekstensi Dart telah terinstal di Visual Studio Code, yang berfungsi sebagai penyedia dukungan sintaks dasar, penyorotan kode, dan analisis statis bahasa pemrograman Dart.

2.8 Konfigurasi Android SDK Build Tools, CMake, dan Android NDK

Pada tahap konfigurasi Android Studio, saya membuka menu SDK Manager dan masuk ke tab SDK Tools untuk memastikan bahwa komponen perakit dasar seperti Android SDK Command-line Tools dan CMake sudah berstatus terinstal (Installed).

Pada tahap penyelesaian masalah (troubleshooting) akibat kegagalan build dari Gradle, saya menginstal komponen tambahan yaitu Android NDK (Side by side) versi 28.2.13676358 secara manual melalui SDK Manager.

BAB III: LAPORAN 3 - PENGEMBANGAN BACKEND API DAN BASIS DATA

3.1 Konfigurasi Lingkungan Backend (Laravel 11)

Pondasi server dibangun menggunakan framework Laravel 11 dengan orientasi arsitektur RESTful API murni. Konfigurasi server diatur melalui berkas .env untuk mendefinisikan port lokal (http://127.0.0.1:8000), koneksi basis data relasional MySQL dengan basis data salut_db, serta secret key otentikasi JWT (JSON Web Token).

3.2 Pemodelan Relasional dan Model Eloquent

Dalam arsitektur basis data relasional SALUT, entitas pengguna dimodelkan melalui kelas User.php yang mengimplementasikan Tymon\JWTAuth\Contracts\JWTSubject. Relasi data dibangun menggunakan relasi one-to-many (hasMany) menuju model StudentSkill dan relasi one-to-one (hasOne) menuju model TracerStudy.

3.3 Visualisasi Struktur Basis Data di phpMyAdmin

Struktur tabel diuji dan dimonitor melalui antarmuka phpMyAdmin. Tabel-tabel utama yang terbentuk antara lain users, student_skills, graduation_schedules, tracer_studies, rapor, dan prestasi.

3.4 Definisi Rute RESTful API (routes/api.php)

Routing API dipetakan secara modular pada berkas routes/api.php dengan proteksi middleware auth:api untuk seluruh transaksi penting.

3.5 Pengujian Endpoint API Login Menggunakan Postman

Hasil pengujian endpoint POST /api/login menggunakan Postman menghasilkan respons HTTP 200 OK dengan pengembalian token JWT bertipe Bearer.
